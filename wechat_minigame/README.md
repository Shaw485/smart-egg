# 怪奇之原 · 微信小游戏版（v190）

这是与网页和 Android 构建隔离的微信小游戏工程。当前同步网页正式主线 v190，共 20 个关卡；首页“创造秘境”入口已下线，已有自定义关卡数据仍保留在本机存储中，没有删除，后续可以通过统一功能开关恢复。

## 正确导入方式

1. 在微信开发者工具选择“小游戏”，导入**当前这份代码所在仓库**内的 `wechat_minigame` 目录；正式发布前先将候选分支快进合并到稳定仓库，再使用 `/Users/bytedance/Documents/trae_projects/game/wechat_minigame`。不要在合并前从稳定目录上传旧版。
2. 不要使用 `/Users/bytedance/WeChatProjects/minigame-1`；那是开发者工具创建的飞机示例工程。
3. 当前 `project.config.json` 已配置《怪奇之原》的正式小游戏 AppID：`wx6f83b5cdbf65041b`；本机当前登录账号已确认具有该 AppID 的管理权限，后台名称为“怪奇之原”。换电脑或换账号后仍应再次核对右侧“基本信息”。
4. 基础库使用 `3.17.1`，画面为横屏。打开工程后先点“编译”，再进行预览和真机调试。
5. 当前项目未接业务服务器，20 关和运行模块全部内嵌在主包中。
6. 上传前必须同时核对 `js/wechat-adapter.js` 显示代码版本 `190`、`js/smart-egg-game.js` 包含 `GAME_CODE_VERSION = 190`，且 `assets/sfx-door-knock.wav` 存在；任一不符都停止上传。

## 当前验收范围

- 首页只显示“踏上旅途”，不显示“创造秘境”；调试入口、关卡码入口和自定义试玩路径同样受功能开关保护。
- 创造秘境关闭时不会注册关卡码系统键盘桥，也不会读取剪贴板；旧自定义数据仍原样保留。
- 主线共 20 关，选关页分 3 页：1–8、9–16、17–20；触屏横滑、鼠标拖动和方向键均可翻页。
- 通关后自动进入下一关，最后一关进入完成页；暂停后可以继续、重来或回到主线选关。
- 触屏支持移动和跳跃多指同时按住；开发者工具支持 `A` 左移、`D` 右移、`空格` 跳跃，`Shift` 用于需要按住空白区域的冻结机制。
- 第 2 关箱子旁不会被纠正到屏幕左侧；第 7、9 关长距离奔跑参照物连续；第 10 关可拖“路”成桥；第 11 关箱子侧面不可穿、顶部可站；第 14 关高塔间距可跳通。
- 第 12 关必须实际从真实地面起手并向左拖动累计足够距离才会发现门，天空、人物和门不计数，底部左右/跳跃键不会被拖地手势抢占，单纯向右行走永远不能让门进入视野；达到阈值后门以限速逐帧动画从屏幕右侧进入，单次大跨度触摸也不会闪到中间。第 15 关墙体拥有侧面、底面和顶面实体碰撞，正常状态不可走穿或跳穿，缩小后才可从通道通过。
- 首页右上角日志按钮可导出诊断日志；在微信环境会优先写入用户目录并调用分享能力，不可分享时复制到剪贴板。
- 真机音频采用稳定的 `InnerAudioContext` 回退；即使音频创建、加载或播放失败，也只记录音频错误，不会中断物理循环或把游戏切成卡死状态。
- v187 恢复 v186 被整体关闭的背景音乐：Web 与微信共用单一原创连续音轨 `assets/bgm-wilds-ambient.wav`，首尾无缝循环；首次真实点击、触摸或按键后启动，暂停或切后台时暂停，返回后从原位置续播。
- v189 不再把异步 `canplay` 当成唯一启动门槛：真实交互后由原生 autoplay 主动启动并以 `onPlay` 确认，`canplay → play` 保留兜底。加载最多等待 10 秒；启动超时或拒绝会释放异常实例并等待下一次交互自动重建，旧实例迟到回调不会干扰新实例。
- 微信系统音频中断、切后台和游戏暂停都会暂停背景音乐，结束中断或返回前台后从既有状态恢复；异常原生 `ended` 会显式补播。背景音量为 0.62，动作和通关音仍独立。
- 旧 380ms 循环短音序永久停用，不再反复产生像故障的点状声；跳跃继续使用独立短促发力/衣料动作音 `assets/sfx-jump-action.wav`。第 5 关敲门使用独立木质采样 `assets/sfx-door-knock.wav`，不再复用短音符、跳跃或落地声音。
- 人物裤腿略微延长；步行使用支撑脚贴地、摆动脚抬起的自然交替，跳跃按上升、顶点、下降分别调整腿部姿势。
- 微信横屏逻辑高度固定为 `1080`，逻辑宽度按完整物理窗口宽高比计算，不设 `2880` 上限；19.5:9、20:9 乃至更长屏幕都会创建对应宽度的真实地图，不横向拉伸人物、门、平台或 UI。`safeArea` 只转换为逻辑内边距避让关键按钮，不再裁切地图或形成单侧黑边。
- 单屏关只延展最外侧地面的真实绘制与碰撞边缘，内部坑宽、出生点、门和机关坐标不变；多屏关继续按每屏 1920 计算。Canvas 只做一次完整等比绘制，不复制最边缘像素，不用模糊、渐变或拖长的假画面填边。2403×1080、左安全区 104 像素的回归设备显示区域完整覆盖 x=0–2403，左侧 gutter 为 0。
- 网页和 Android 版本仍固定使用 `1920×1080`；本次响应式规则只在 `__wxMiniGame` 环境生效。

## 从网页主线同步

微信运行文件必须由同步脚本生成，不要直接手改 `js/smart-egg-game.js`：

```bash
node wechat_minigame/tools/sync-web-runtime.js
node wechat_minigame/tools/sync-web-runtime.js --check
```

脚本会同步网页游戏逻辑、20 关离线包、碰撞模块和正式机制模块，并注入微信隔离环境、内嵌关卡冷启动及系统键盘适配。每个同步文件都会输出带时间、模块、字节数和 SHA-256 的结构化诊断记录；`--check` 只校验、不写文件。

## 日志与独立调试

运行日志采用结构化事件，包含时间、等级、模块、事件、会话及非敏感上下文。主运行时日志为内存环形缓冲，最多 10000 条；高频 `physics` 模块在生产默认关闭，避免影响帧率。密码、令牌、授权头、Cookie、私钥等字段会递归脱敏，错误文本中的 Bearer、Token 查询参数与 JWT 也会脱敏。

可在开发者工具调试控制台中使用：

```js
_logModuleStatus()                         // 查看各模块开关
_setLogModule('input', false)              // 独立关闭输入日志
_setLogModule('collide', true)             // 独立开启碰撞日志
_setLogModule('viewport', true)            // 独立开启主运行时视口日志
_findLogs('', 'level-load')                // 只筛选关卡加载
_findLogs('', 'viewport')                  // 只筛选逻辑视口和地图适配
_findLogs('', 'audio')                     // 背景音乐与动作音生命周期
_findLogs('error')                         // 筛选错误事件
__debug.getAudioDiagnostics()              // 背景音乐状态、音量、位置与最后错误
__debug.getViewportLayout()                // 当前逻辑视口、世界边界、相机与 backing size
__debug.inspectLevelViewport(__SMART_EGG_LEVELS__[3]) // 对比关卡适配前后，原数据不被修改
_exportLogs()                              // 导出完整诊断包
```

主要模块包括 `runtime`、`viewport`、`feature`、`state`、`input`、`level-load`、`collide`、`audio`、`storage`、`network`、`export` 和各 `mechanic:*` 子模块。`audio` 会区分背景音乐的加载、首次交互启动、播放、暂停、恢复、错误、销毁与动作音请求；只写状态变化，不逐帧或逐音符刷屏。微信适配层另保留最多 200 条 `wechat-adapter:*` 日志，并随诊断包一起导出；每条带独立 `sessionId` 和递增 `seq`。通过 `__SMART_EGG_ADAPTER_LOG_CONFIG__.getModules()`、`.setModule('viewport', false)` 和 `.find('viewport', 'viewport-updated')` 可独立开关及筛选安全区、逻辑尺寸、显示区域和边缘策略；其他模块也可使用相同方式单独调试。低频、可执行的 `audio-core` 生命周期与失败日志在生产默认开启；高频 `input`、`audio` 详情在生产默认关闭，需要复现时分别执行 `.setModule('input', true)` 或 `.setModule('audio', true)`。`runtime`、`viewport`、`feature`、`storage`、`network`、`export` 同样默认开启。复现完成后关闭高频模块；不要在日志里手工附加 AppSecret、AccessToken、用户隐私或其他敏感信息。

v184 会持久化精简的 `previousFault` 和 `lastFault`，每条故障中的 `lastAction` 记录故障前最后动作；完整逐帧日志仍只保存在有上限的内存环形缓冲中。若真机已经卡住、来不及手动导出，直接关闭并重新打开游戏，在首页右上角点击日志导出，新的诊断包会带回上次会话的异常与最后动作。

## 工程结构

- `game.js`：微信小游戏入口和加载顺序。
- `js/wechat-adapter.js`：微信 Canvas、触控、键盘、音频、存储、生命周期和日志导出适配。
- `js/levels.js`：20 个正式关卡的内嵌离线数据。
- `js/physics-collision.js`：主线碰撞模块。
- `js/accepted-mechanics.js`：第 13–20 关正式机制模块。
- `js/smart-egg-game.js`：由同步脚本生成的 v190 微信运行时。
- `tools/sync-web-runtime.js`：确定性同步与一致性检查。
- `tests/smoke-test.js`：微信隔离环境启动和功能回归。
- `tests/responsive-viewport-test.js`：完整窗口比例、物理/逻辑安全内边距、等比呈现、输入换算和超宽精确地图矩阵回归，并验证没有单侧黑边或边缘复制。
